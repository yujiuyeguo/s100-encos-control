# ENCOS CAN5 逐档频率测试

测试日期：2026-11-17。本机通过SSH在S100运行；MCU1现有4.0.5固件、单台EC-A6408-P2-25、ID1，经典CAN。

## 结果

每档5秒，同一进程依次50/100/250/500/1000/2000Hz；无接口错误、调度漏周期或电机故障，合计19,500帧提交被接受、19,500帧匹配类型3反馈。

新版工具已完成调度优化，默认profile变为rt；本报告保留优化前普通线程结果。新结果见 [时序优化报告](ENCOS_TIMING_TUNING_20261117.md)，复现本报告设置可显式传 `--profile baseline`。

## 方法与边界

- 固定发送0x001、DLC3、`67 00 00`，请求零力矩与类型3回复；匹配CAN5/ID1、经典CAN、DLC8、类型3的电机反馈。没有施加非零力矩、使能、松闸/锁闸、设零或修改电机参数。最大绝对转速0.008rpm，电流反馈均0A。
- 每档开始先观察200ms，未收到非请求类型3反馈；发送结束后停止TX并排空接收500ms，将晚到回复计入本档。
- 使用单线程非阻塞接收，专用build配置recv_timeout=0；按steady_clock定时，超过周期则记录跳过时隙，不用追赶连发掩盖延迟。本轮各档skipped_slots均0。
- 未启用FIFO实时优先级或绑核；环境为当时板端正常业务负载，未额外叠加机器人控制、推理或感知压力。临时运行Linux时间同步程序，未重复初始化MCU同步服务；本次程序均有界退出。
- ENCOS回复不携带可匹配到每条控制命令的序号。因此数量相等支持“本窗口未发现回复缺口”，不证明绝无重复/丢失抵消，也不能分离去程、回程或电机回复策略造成的缺口；未接独立总线分析仪。
- 本次是3字节直接力矩帧 + 8字节回复，未测试8字节MIT控制帧、多电机、多总线同时运行或长期稳定性，也不等同于完整机器人250Hz/硬实时验收。
- 原始日志仍包含SDK非阻塞空读ret=-11的日志；程序将对应CANHAL -303计为空读，不计接收错误。SDK日志开销也属于本次测量环境，未将其包装成无日志实时基准。

## MCU统计与滚动序号告警

同进程连续测试前后CAN5 TX 20458→39958、RX 20457→39957，均恰好增加19,500；溢出/忙/PDU错误增量均0。

初版每档重启进程时RollCntErr增加6；改为同进程连续6档后，仅在新进程初始化边界增加1（17→18）。这支持告警由CANHAL进程重建后滚动序号复位触发的解释；不能把它计为6档各丢一帧。完整收发计数及协议应答数量均对应。

## 人工操作（在S100上）

本机woker不是S100。先SSH进入sunrise账户，进入板端项目：

```bash
cd ~/s100-encos-control
bash ws/tools/field/encos_rate.sh --prepare
# 离线预览，不初始化CANHAL、不发帧
bash ws/tools/field/encos_rate.sh --sweep --seconds 5
# 真机：按50到2000Hz逐档发送零力矩帧，每档5秒
bash ws/tools/field/encos_rate.sh --sweep --seconds 5 --hardware
# 单独测250Hz
bash ws/tools/field/encos_rate.sh --hz 250 --seconds 5 --hardware
```

需要保持已初始化的MCU与时间同步环境，CAN5不得被其他CANHAL程序并发占用。不要为重复测试再次执行timesync --init-mcu。测试频率档位为本探针的测试范围，不更改encos_jog此前取消的人为限值。

源码：`ws/tools/field/encos_rate.cpp`、`encos_rate.sh`。证据：`log/encos_rate/continuous.txt`、`continuous_results.json`、`mcu_continuous_before.txt`、`mcu_continuous_after.txt`、`summary.json`。初版分进程数据保留在同目录各hz*.txt及results.json，不混作最终连续测试结果。
