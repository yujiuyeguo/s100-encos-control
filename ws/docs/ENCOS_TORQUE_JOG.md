依据本目录《ENCOS+调试技术手册+V1.16.pdf》9.1.4节，直接力矩模式采用0.01 N·m单位的有符号16位数，大端排列：

- CAN5 / ID1，标准经典CAN，DLC3；`67 00 32` = +0.5 N·m，请求类型3反馈。
- `67 00 64` = +1 N·m，请求类型3反馈。
- `67 00 00` = 零力矩；撤去力矩不等于主动制动，也不保证输出轴立即停稳。
- 请求类型3反馈包含输出端转速RPM、电机相电流、温度和错误信息。相电流乘驱动配置的转矩系数仅为估算，不能当作实测输出扭矩。

## 工具与使用

`ws/tools/field/encos_jog.sh` 和 `encos_jog.cpp` 是独立人工调试入口，不改变原项目和默认mock节点。固定CAN5、ID1；默认正向0.5 N·m、0.2秒。`--torque` 只按协议的int16、0.01 N·m单位校验，可输入-327.68～327.67 N·m；这是报文编码范围，不代表电机具备对应输出能力。`--seconds` 接受任意正的有限数值，无人为时长上限。原20rpm运行阈值、1rpm启动阈值、1 N·m和5秒上限均已移除，不宣称硬实时。

在S100中：

```bash
cd ~/s100-encos-control
bash ws/tools/field/encos_jog.sh --prepare
# 默认预览，不初始化CANHAL、不发帧
bash ws/tools/field/encos_jog.sh
# 实际仅查询抱闸、速度、转矩系数及CAN超时保护，无运动命令
bash ws/tools/field/encos_jog.sh --status --hardware
```

本次型号按用户要求不进行抱闸操作；再次进行相同短时测试：

```bash
bash ws/tools/field/encos_jog.sh --model EC-A6408-P2-25 --hardware
```

当前参数预览/运行（已无20rpm提前退出条件）：

```bash
# 离线预览
bash ws/tools/field/encos_jog.sh --model EC-A6408-P2-25 --seconds 5 --torque 1
# 真机：每次手动调用都会产生新的运动请求
bash ws/tools/field/encos_jog.sh --model EC-A6408-P2-25 --seconds 5 --torque 1 --hardware
```

`--model` 也接受 `EC_A6408_P2_25`，它明确选择本次不操作抱闸的路径，跳过抱闸查询/操作；不根据型号猜测应答。其他型号暂不支持此选项。

仅发送零力矩并读反馈（无正力矩请求）：

```bash
bash ws/tools/field/encos_jog.sh --model EC-A6408-P2-25 --zero-only --hardware
```

不指定型号时仍要求抱闸查询确认释放；`--release-brake` 是另一个明确允许松闸的模式，不能与上述型号选项组合，本次未使用。带抱闸型号松闸后保持释放，工具不会在输出轴可能转动时自动吸合抱闸。

当前只要求前置速度反馈有效且无电机故障，不要求静止，也不根据转矩系数或500ms超时阈值拒绝启动。运行期间收到电机故障或任一轮缺少新鲜有效控制反馈时，仍按通信/设备错误处理并尝试撤去力矩。转矩系数与电机超时仅查询、记录，不修改电机内部配置。正常完成及力矩阶段异常退出会尝试发送零力矩；Ctrl+C/SIGTERM触发退出。进程被强杀、总线中断或系统故障时不能保证零力矩送达，需依靠已查询的电机超时保护。无论是否收到API成功返回，均须按反馈判断运动和结束状态。
